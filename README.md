# Cold Outreach Email Builder

A Python command-line application that generates personalized networking emails using OpenAI's API.

Rather than simply generating an email from a prompt, the application uses a multi-stage workflow to draft, evaluate, and conditionally revise an email based on structured feedback.

**Current version:** V2.0 — Conditional AI Workflow

## Overview

Writing effective cold outreach emails requires more than good grammar. The sender needs to identify a meaningful reason for contacting a particular person, communicate a focused learning goal, and make a low-pressure request.

This project explores how an AI-powered workflow can help with those decisions while minimizing unnecessary revisions and unsupported factual claims.

## Features

- **Structured input collection:** Collects sender background, recipient context, relationship angles, learning goals, tone, and desired email length.
- **Input validation:** Applies defaults and flags vague or incomplete information.
- **AI email generation:** Creates an initial draft using the OpenAI API.
- **Structured evaluation:** Evaluates the draft and returns feedback in JSON format.
- **Conditional revision:** Uses deterministic Python logic to decide whether another API call is necessary.
- **Factual consistency checks:** Instructs the evaluator and reviser to identify claims unsupported by the supplied user context.

## Workflow

```text
User Inputs
    |
    v
Input Validation & Defaults
    |
    v
Prompt Construction
    |
    v
AI Email Generation
    |
    v
AI Evaluation (Structured JSON)
    |
    v
Python Decision Tree
    |
    +---- Revision Needed? ----+
    |                          |
   Yes                         No
    |                          |
    v                          |
AI Revision                    |
    |                          |
    +------------+-------------+
                 |
                 v
             Final Email
```

The decision tree triggers revision when:

1. The evaluator identifies misrepresentation.
2. The overall score is below 8 out of 10.
3. The evaluator recommends revision and identifies an issue other than `none`.

Otherwise, the original draft is preserved.

This design separates AI-generated feedback from the application's final decision about whether to revise.

## Getting Started

### Prerequisites

- Python 3.10 or newer
- An OpenAI API key
- Access to the configured OpenAI model

### Installation

Clone the repository:

```bash
git clone https://github.com/YOUR_USERNAME/cold-outreach-prompt-generator.git
cd cold-outreach-prompt-generator
```

Create and activate a virtual environment:

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

Install dependencies:

```bash
pip install -r requirements.txt
```

Create a `.env` file in the project directory using `.env.example` as a template:

```text
OPENAI_API_KEY=your_api_key_here
```

### Running the Application

```bash
python main.py
```

Follow the terminal prompts to enter sender and recipient information. The application will generate an initial email, evaluate it, and revise it only when the decision logic determines that revision is necessary.

API usage may incur charges.

## Project Structure

| File | Purpose |
|---|---|
| `main.py` | Collects user inputs and controls the application workflow |
| `prompt_template.py` | Builds prompts for email generation, evaluation, and revision |
| `ai_client.py` | Handles OpenAI SDK and HTTP API requests and parses responses |
| `validation.py` | Applies defaults, normalizes inputs, and produces context warnings |
| `test_decision_tree.py` | Tests the conditional revision logic |
| `test_json_parsing.py` | Tests malformed JSON handling |
| `test_misrepresentation.py` | Exercises the evaluator's response to fabricated claims |
| `LEARNING_LOG.md` | Documents the development process and technical learning |

## Testing

Run the available test scripts:

```bash

```

The project also includes an API-dependent misrepresentation test:

```bash
python test_misrepresentation.py
```

This test may incur API charges.

## Limitations

- Operates through a command-line interface; no graphical user interface is provided.
- Relies on user-supplied information rather than independently researching recipients.
- Factual consistency checks compare email claims against supplied context, not external sources.
- Evaluation scores and revision recommendations are generated by an LLM and may vary.
- The application does not guarantee that revisions improve email quality.
- No persistent database, user accounts, or outreach tracking are implemented.
- The application is a learning project, not a production-ready outreach platform.
